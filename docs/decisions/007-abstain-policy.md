# 007 When the tool refuses to answer
**Decision.** The engine returns needs_ca with no single rate when: the models abstain; the CA marks the payment unclear; there is possible PE exposure; "make available" is contested (both branches are computed and shown); or treaty protection is missing for something that may be business profits. It returns refused when a rule is stale or no Act rule covers the payment date.
**Why.** These are exactly the points where Indian practice is litigated. A tool that answers them confidently moves liability onto a CA who did not think. A tool that lays out both readings with the arithmetic done saves the CA's time without taking the decision.
**Metric.** The evaluation's headline safety number is "wrong and confident": a wrong rate shown as Computed. An escalation that a CA has to resolve is counted as safe, not as a pass.
**Added after the first live run.** The eval caught one "wrong and confident" result: on sg-monitoring-contested, one model said "technical services, make-available contested" and two said "business profits" because the know-how stays with the vendor. The 2-1 majority won, the engine computed nil, and the screen said Computed. The disagreement was the make-available question itself. Rule added: when counted votes split between technical services and business profits, the consensus is "make available: contested", so the CA sees both outcomes computed. The cost: some cases where the models disagree only on the label (uk-research-no-ma) are now escalated too. Escalating a non-dispute costs a CA two minutes; certifying a wrong nil rate costs a penalty and the CA's signature.
**Added after the first run on new cases.** adv-transition-straddle-april-2026 (Germany) was escalated because one model said make-available was "not applicable" and the other said "no". Germany has no make-available test, so both readings give 10%. Rule added in the engine, not the vote: when both branches of a contested make-available give the same status, basis and rate, the engine returns that result with a trace line saying the dispute does not matter. Found on a case the system had not seen; the fix itself has so far only been checked on that case and a unit test.
